# English and French

The client context restores `payflow.locale` after hydration, starting with the same English markup as the static export. The header picker works without locale routes, a backend or browser storage. It updates the document language and synchronizes changes across tabs. Locale changes retain the mounted wallet provider and page state.

Application text belongs in both catalogs. Use `t(key, values)` for full phrases and `translateMessage` only for messages generated by Payflow's own validators. Merchant names, addresses, transaction hashes, server/wallet diagnostics and code examples retain their original content. Language names use their own language. Static install metadata remains English; the client document title follows the selected language.

Display money is derived from exact bigint/string values, never floating-point amounts. Dates use the selected locale and UTC, preserving the contract's day. French entry treats commas as decimal separators, including `1,234`; switching language converts the decimal mark of valid amount drafts without changing their value. Invalid drafts remain visible for correction. Contract arguments, CSV exports, identifiers, date-input values and embed code stay canonical. The existing parsing behavior remains available to callers that do not supply a locale.

Run `npm run lint`, `npm run typecheck`, `npm test` and `npm run build`. Locale tests cover exact large/small amounts, six-decimal tokens, ambiguous separators, language switching with active form state, blocked storage, cross-tab changes and static hydration. Existing wallet, account, merchant and contract-only tests remain enabled.
